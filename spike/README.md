# M0 可行性验证 spike

**目标**：用真实音频跑通「音频 → 调性/BPM/和弦 → 音色套路 → 设备参数建议」最短链路，评估免费开源工具（librosa 等）能出什么质量，决定核心功能最终形态和是否需要付费 API。

## 使用方法

```bash
# 分析任意音频文件
spike/.venv/Scripts/python.exe spike/analyze.py spike/songs/xxx.mp3

# 生成合成测试音频（已知和弦进行 C-G-Am-F @120BPM，校验工具链用）
spike/.venv/Scripts/python.exe spike/make_synthetic.py
```

## 文件说明

- `analyze.py`：分析脚本。输出 JSON：时长、BPM、节拍数、调性 Top3（Krumhansl-Schmuckler 相关法）、粗略和弦序列（chroma + 三和弦模板匹配）、能量/亮度特征、套路归类（启发式规则）、设备参数建议（套路模板映射）
- `make_synthetic.py`：合成测试音频生成器
- `songs/`：测试音频。`test_track.mp3` 为 CC 授权样例（howler.js 示例音频）；**请把 3 首真实目标歌曲（一首 Beyond + 两首动漫歌）放进此目录**，spike 才有真实结论

## 已知局限

- 粗略和弦估计用简单模板匹配，准确率有限；更强的和弦识别（madmom 的 CNN 模型等）在本机 Python 3.13 下暂不可用，需另建环境或改用付费 API
- 套路归类是启发式规则，正确性依赖真实歌曲数据调优
- 短于 30 秒的音频片段 BPM/调性估计不稳定

## M0 对拍结果（2026-08-15，5 首真实歌曲 vs 社区权威数据）

BPM 采用「beat_track 半速加倍」规则（测值 <100 时 ×2）。

| 歌曲 | BPM 修正后 | 真实 BPM | 调性 spike | 真实调性 | 套路归类 | 和弦 |
|---|---|---|---|---|---|---|
| NO, Thank You!（K-ON!!） | 178.2 | 181 | E 小调 ✗ | A 小调 | 失真节奏 ✓ | 粗略 |
| 空の箱（GBC） | 147.6 | 148 | F# 小调 ✓平行 | A 大调 | 失真节奏 ✓ | 粗略 |
| KiLLKiSS（Ave Mujica） | 198.8 | 200 | E 小调 ✓ | E 小调 | 失真节奏 ✓ | 粗略 |
| 雑踏、僕らの街（GBC） | 172.3 | 171 | E 小调 ✓ | E 小调 | 失真节奏 ✓ | 粗略 |
| 星座になれたら（孤独摇滚） | 123.0 | 123 | G# 大调 ✓ | Ab（=G#）大调 | 失真主音（主旋律吉他，合理待校准） | 粗略 |

**结论（M0 完成）**：
- **BPM：可用**——修正后误差 ≤1.5%（局限：真实 <100 BPM 的慢歌会被误判加倍，需后续用节拍强度比较法处理）
- **调性：参考可用**——4/5 命中（唯一失误《NO, Thank You!》被前奏 B 大三和弦拉偏；聚合 chroma 在强力弦摇滚上有固有歧义，产品必须标注置信度）
- **套路归类：初步可用**——4/5 合理，但样本集中于失真摇滚，清音类歌曲仍需校准
- **和弦识别：薄弱**——每首仅 3~9 段、漏约一半和弦；需靠种子曲库数据或付费和弦识别 API
- **产品策略**：种子曲库数据优先 → AI 识别作参考并标置信度 → 人工纠错。M1 无技术依赖可开工；付费 API 决策留到 M2 前
